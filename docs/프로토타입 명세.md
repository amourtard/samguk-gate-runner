# 프로토타입 명세

클로드 코드에 넘기는 2주 프로토타입의 구현 기준이다. 수치는 모두 초기값이고, 플레이하면서 데이터 파일에서 고친다.

## 1. 기술 기준

3D 쿼터뷰, 세로 화면, 도형만으로 만든다. 모델, 텍스처, 애니메이션은 쓰지 않는다.

| 항목 | 기준 |
| --- | --- |
| 엔진 | Godot 4.6 계열 안정 버전. 2026년 4월 기준 4.6.2까지 확인했고([릴리스 목록](https://godotengine.org/blog/release)), 이후 버전이 나왔으면 삼국지 디펜스와 같은 버전으로 맞춘다 |
| 언어 | GDScript |
| 렌더러 | Mobile |
| 화면 | 세로 1080×1920, 가로 폭 고정으로 늘림 |
| 카메라 | 원근 Camera3D. 아군 뒤쪽 위에서 약 50도로 내려다보고 아군을 따라간다 |
| 월드 | 도로는 −Z 방향 직선, 폭 10m. 아군 좌우 이동 범위는 중심에서 ±4m |
| 병사 표현 | MultiMeshInstance3D. 보병은 상자, 궁병은 가는 원기둥, 기병은 긴 상자. 아군 파랑, 적 빨강 |
| 조작 | 화면 아무 곳이나 좌우 드래그(상대 이동). 에디터에서는 마우스 |
| 목표 성능 | 중급 안드로이드 폰에서 60fps, 최저 30fps |
| 실행 확인 | 에디터 실행 우선. 폰 빌드는 단계 6에서 한 번 |

## 2. 씬과 스크립트 구조

전투 계산은 화면과 분리한다. 병력 수와 피해는 순수 계산 스크립트가 맡고, 뷰 스크립트는 그 결과를 그리기만 한다.

| 파일 | 역할 |
| --- | --- |
| scenes/main.tscn | 화면 전환: 장수 선택 → 달리기 → 책략 선택 → 결과 → 강화 |
| scenes/run.tscn | 한 판. 도로, 아군, 적 무리, 게이트, 보스, HUD를 담는다 |
| scenes/gate\_pair.tscn | 좌우 게이트 한 쌍 |
| scenes/enemy\_group.tscn | 적 무리 하나 |
| scenes/boss.tscn | 보스 |
| scenes/ui/ | 장수 선택, 책략 3택, 결과, 강화 화면 |
| scripts/game\_state.gd | 자동 로드. 현재 판 상태, 금화, 영구 강화 수치와 파일 저장 |
| scripts/data\_db.gd | 자동 로드. data 폴더의 JSON을 읽어 제공 |
| scripts/army.gd | 병력 모델. 수, 병종, 체력 합계, 보정치. 노드에 의존하지 않는다 |
| scripts/combat.gd | 교전 계산. 노드에 의존하지 않는다 |
| scripts/army\_view.gd | army.gd의 수를 MultiMesh로 그린다. 표시 상한 처리 |
| scripts/stage\_builder.gd | 스테이지 데이터로 도로 위에 게이트와 적을 배치 |
| scripts/gate.gd, strategy.gd, boss.gd | 각 요소의 효과 적용 |
| scripts/hud.gd | 병력 수, 다음 적 구성 띠, 숫자 팝업 |
| scripts/sfx.gd | 효과음 3종 재생 |
| scripts/pick\_log.gd | 게이트와 책략 선택, 판 결과를 user:// 아래 CSV로 기록 |
| data/\*.json | 3장의 데이터 파일 |

## 3. 데이터 파일과 초기값

모든 수치는 data 폴더의 JSON에 두고 코드에 숫자를 직접 쓰지 않는다. 아래 값은 출발점이고 플레이하면서 고친다.

**units.json: 병종 (병사 1명 기준)**

| 병종 | 체력 | 초당 피해 | 사거리 | 특수 |
| --- | --- | --- | --- | --- |
| 보병 | 10 | 2 | 근접 | 없음 |
| 궁병 | 6 | 3 | 12m | 닿기 전부터 사격 |
| 기병 | 14 | 3 | 근접 | 첫 접촉 시 1회 돌격 피해 8 |

상성 배율은 유리한 쪽이 주는 피해 ×1.5다. 궁병이 보병에게, 기병이 궁병에게, 보병이 기병에게 유리하다. 나머지 조합은 ×1.0.

아군은 한 번에 한 병종만 가진다. 병종 전환 게이트는 전원을 바꾼다. 적 무리는 병종을 섞을 수 있다.

**gates.json: 게이트 5종**

| 종류 | 색 | 효과 초기값 |
| --- | --- | --- |
| 증원 | 파랑 | +10, +20, +30명 또는 ×2 (×2는 2구간부터) |
| 병종 전환 | 초록 | 지정 병종으로 전원 전환, 병력 −20% |
| 강화 | 빨강 | 공격속도 +50%에 병력 −30%, 또는 받는 피해 −30%에 병력 −20% |
| 도박 | 보라 | 50% 확률로 ×3, 50% 확률로 ÷2 |
| 함정 | 회색 | 병력 −30%, 판 종료 시 금화 +100 |

한 쌍의 좌우는 서로 다른 종류로 둔다. 도박은 증원(+N)과만 짝짓는다.

**strategies.json: 책략 9종 (3계열 × 3)**

| 계열 | 책략 | 효과 초기값 |
| --- | --- | --- |
| 물량 | 징병 | 증원 게이트 효과 +50% |
| 물량 | 의병 | 구간 시작 시 +10명 |
| 물량 | 횡진 | 근접 동시 교전 수 +8 |
| 정예 | 정병 | 즉시 병력 −40%, 공격력 ×2 |
| 정예 | 철갑 | 받는 피해 −25% |
| 정예 | 선봉 | 첫 접촉 피해 추가(병력 수 × 4). 기병은 돌격 피해 ×2 |
| 화공 | 불화살 | 원거리 피해의 50%를 3초간 지속 피해로 추가. 궁병이 아니면 5초마다 병력 수 × 1의 일제 사격 |
| 화공 | 화계 | 적 무리와 교전 시작 시 그 무리 체력의 15% 피해 |
| 화공 | 연환 | 지속 피해 중인 적이 받는 피해 +25% |

같은 계열 2개를 모으면 추가 효과가 붙는다. 물량은 증원 게이트마다 +10명, 정예는 공격력 +30%, 화공은 지속 피해 2배. 계열 효과가 켜지면 병사 색이 바뀐다(물량 하늘색, 정예 금색, 화공 주황).

**heroes.json: 장수 3명**

| 장수 | 시작 병종 | 시작 병력 | 고유 기술 (자동 발동) |
| --- | --- | --- | --- |
| 관우 | 기병 | 12 | 15초마다 전방 적 무리에 병력 수 × 5 피해 |
| 장비 | 보병 | 16 | 15초마다 3초간 받는 피해 −50% |
| 제갈량 | 궁병 | 12 | 18초마다 4초간 사거리와 공격속도 +50% |

**stages.json: 스테이지 5개**

각 스테이지는 3구간이고, 구간마다 게이트 2\~3쌍과 적 무리 2개를 둔다. 끝에는 보스 장각이 나오며 체력만 바꿔 재사용한다.

| 스테이지 | 적 구성 | 적 병력 합계 | 지형 | 보스 체력 |
| --- | --- | --- | --- | --- |
| 1-1 | 보병 100% | 60 | 평지 | 400 |
| 1-2 | 보병 70%, 궁병 30% | 90 | 평지 | 600 |
| 1-3 | 궁병 60%, 보병 40% | 120 | 2구간 좁은 다리 | 800 |
| 1-4 | 기병 50%, 보병 50% | 160 | 평지 | 1,100 |
| 1-5 | 보병 40%, 궁병 30%, 기병 30% | 220 | 3구간 좁은 다리 | 1,500 |

**upgrades.json: 영구 강화 2종**

| 시설 | 효과 | 비용 |
| --- | --- | --- |
| 병영 | 레벨당 시작 병력 +2 | 100 × 다음 레벨 금화 |
| 무기고 | 레벨당 공격력 +5% | 150 × 다음 레벨 금화 |

금화는 클리어 시 100 × 스테이지 번호, 실패 시 그 30%를 준다.

**tuning.json: 공통 수치**

| 항목 | 초기값 |
| --- | --- |
| 전진 속도 | 초당 8m |
| 좌우 최대 속도 | 초당 12m |
| 구간 길이 | 150m |
| 교전 중 전진 속도 | 평소의 20% |
| 게이트 앞 감속 | 12m 앞에서 속도 50%, 켜고 끄기 가능 |
| 근접 동시 교전 수 | 20명, 좁은 다리 8명 |
| 원거리 동시 사격 수 | 40명 |
| 병사 표시 상한 | 200개. 넘으면 비율로 묶어 표시 |
| 숫자 팝업 | 0.1초 동안 1.5배 확대 후 복귀 |
| 화면 흔들림 | 충돌 시 0.08초 |

## 4. 전투 규칙

전투는 무리 단위의 숫자 계산이고, 병사 개체끼리의 충돌 판정은 하지 않는다. 계산은 0.1초 간격으로 돈다.

1. **무리의 체력**: 무리 체력 합계 = 병력 수 × 병사 체력. 피해는 합계에서 빼고, 병력 수 = 합계 ÷ 병사 체력을 올림한 값이다.
2. **원거리 단계**: 궁병은 적 무리가 사거리 안에 들어오면 쏜다. 피해 = 사격 인원(최대 40) × 초당 피해 × 상성 배율 × 보정치. 적 궁병도 같은 규칙으로 아군을 쏜다.
3. **접촉**: 두 무리의 거리가 1m 이하면 근접 교전이다. 아군 전진 속도가 20%로 떨어지고, 적 무리가 전멸하면 원래 속도로 돌아온다.
4. **기병 돌격**: 기병은 접촉하는 순간 한 번, 병력 수 × 돌격 피해를 준다.
5. **근접 단계**: 양쪽이 동시에 피해를 준다. 피해 = 교전 인원(최대 20, 좁은 다리 8) × 초당 피해 × 상성 배율 × 보정치.
6. **섞인 적 무리**: 적 무리는 병종별로 체력을 따로 가진다. 아군 피해는 앞줄 병종부터 들어가고(보병, 기병, 궁병 순), 상성 배율은 맞는 병종 기준으로 계산한다.
7. **패배**: 아군 병력이 0이 되면 판이 끝난다.

**보스 장각**

- 도로를 좌, 중, 우 3개 구역으로 나눈다. 5초마다 한 구역에 1.2초 동안 붉은 예고를 띄운 뒤 공격한다.
- 공격 순간 아군 중심이 그 구역에 있으면 병력의 25%를 잃는다.
- 접촉 중에는 초당 2명씩 아군이 줄어든다.
- 아군은 근접 단계 규칙으로 보스 체력을 깎는다. 궁병은 사거리에서 쏠 수 있다.

**연출 최소 기준**

- 효과음 3종: 게이트 통과, 화살 발사, 타격. 무료 공개 음원을 쓴다.
- 병력 수가 바뀔 때마다 무리 위 숫자가 팝업되고, 게이트 통과 시 "+20" 같은 변화량이 뜬다.
- 근접 접촉 순간과 보스 공격 순간에 화면이 짧게 흔들린다.
- 궁병 사격은 날아가는 작은 상자로 보인다.

## 5. 단계별 작업과 완료 조건

한 번에 한 단계만 시키고, 직접 플레이해서 완료 조건을 확인한 뒤 다음으로 넘어간다.

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1 | 프로젝트 생성, 도로, 카메라, 드래그 이동, 병력 MultiMesh 표시 | 세로 화면에서 파란 무리가 달리고 좌우로 움직인다. 병력 수를 바꾸면 무리 크기가 바뀐다 |
| 2 | 데이터 로더, 적 무리, 전투 규칙 1\~7 | 적 무리와 싸워 병력이 줄고, 0이 되면 패배 화면이 뜬다. 병종을 바꾸면 결과가 달라진다 |
| 3 | 게이트 5종, HUD(병력 수, 다음 적 구성 띠), 효과음과 숫자 팝업, 게이트 앞 감속 | 게이트를 고르면 병력과 병종이 바뀌고 소리와 숫자가 나온다. 감속을 설정으로 켜고 끌 수 있다 |
| 4 | 책략 9종, 3택 화면, 계열 효과와 색 변화, 선택 기록 | 3구간을 달리며 책략을 3번 고른다. 같은 계열 2개면 병사 색이 바뀐다. 기록 파일이 쌓인다 |
| 5 | 스테이지 5개, 보스, 장수 3명과 선택 화면, 결과 화면 | 장수를 골라 1-1부터 1-5까지 순서대로 도전할 수 있다. 보스 예고를 피할 수 있다 |
| 6 | 영구 강화 2종, 금화, 저장, 안드로이드 빌드 | 판 사이에 강화하고 껐다 켜도 유지된다. 폰에서 돌려 병사 200개일 때 프레임을 확인한다 |

단계 6이 끝나면 기획서 9장의 검증 기준으로 판정한다.

## 6. 범위 밖과 작업 규칙

아래는 요청하지 않는 한 만들지 않는다.

- 3D 모델, 텍스처, 애니메이션, 파티클 연출, 배경음
- 장수 수집, 조각, 등급, 장비
- 광고, 결제, 스토어 등록
- 튜토리얼, 스토리, 설정 화면, 다국어
- 서버 통신, 계정, 순위
- 책략 9종과 게이트 5종을 넘는 추가 콘텐츠

**CLAUDE.md에 넣을 규칙**

- 이 탭의 명세를 기준으로 하고, 명세에 없는 것은 만들기 전에 묻는다.
- 수치는 반드시 data 폴더의 JSON에 둔다. 코드에 숫자를 직접 쓰지 않는다.
- army.gd와 combat.gd는 노드와 렌더링에 의존하지 않는다.
- 한 단계가 끝나면 멈추고, 무엇을 만들었고 어떻게 확인하는지를 알려준다.
- 사용하는 Godot 버전의 문서를 기준으로 API를 확인한다. 3.x 문법을 쓰지 않는다.
- 단계를 마칠 때마다 Godot을 헤드리스로 실행해 스크립트 오류가 없는지 확인한다.
- 재미와 손맛은 판단하지 않는다. 수치 조정은 사람이 플레이한 뒤 요청한다.
