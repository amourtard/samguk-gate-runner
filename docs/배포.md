# 배포와 플레이 기록

웹 빌드를 Vercel에 올리고, 플레이 기록을 모아 분석하는 절차다. 구조는 프로토타입_명세.md의 "플레이 기록 수집" 참조.

## 구조

```
PC에서 git push (main)
  → GitHub Actions(.github/workflows/deploy.yml, 원본은 tools/deploy.yml)가 Godot 웹 빌드를 만들고 server/와 합쳐 deploy 브랜치에 올림
  → Vercel이 deploy 브랜치를 배포
       public/      게임(index.html, index.wasm, index.pck)
       api/log      게임이 보낸 사건을 Postgres에 저장
       api/export   모은 사건 내려받기(EXPORT_TOKEN 필요)
  → tools/analyze_logs.py가 내려받아 보고서를 만듦
```

- 빌드 결과물은 main에 넣지 않는다. deploy 브랜치는 매번 통째로 바뀐다(이력이 쌓이지 않는다).
- Cloudflare Pages는 파일당 25MB 제한이 있어 쓰지 않았다. Godot 4.7.2 웹 빌드의 index.wasm이 약 40MB다.
- main에는 배포를 끄는 vercel.json이 있다(문서와 소스가 공개되지 않게). 배포 설정은 server/vercel.json이다.

## 처음 한 번 할 일 (사람이 한다)

화면의 이름은 Vercel이 바꿀 수 있다. 2026-11-12에 이 절차를 실제 Vercel에서 확인하지는 못했다.

1. PC에서 작업 흐름 파일을 제자리에 복사하고 푸시한다. 검토 세션의 파일 도구는 `.github` 폴더에 쓸 수 없어서 `tools/deploy.yml`에 두었다.

   ```
   cd C:\git\samguk-gate-runner
   mkdir .github\workflows
   copy tools\deploy.yml .github\workflows\deploy.yml
   git add .github
   git commit -m "단계 7: 웹 빌드 작업 흐름"
   git push origin main
   ```
2. GitHub 저장소의 Actions 탭에서 "웹 빌드와 배포 브랜치 갱신"이 끝나기를 기다린다(처음은 5분쯤, 다음부터 2~3분). 끝나면 deploy 브랜치가 생긴다.
   - 실패하면 Settings → Actions → General → Workflow permissions가 "Read and write permissions"인지 확인한다.
3. Vercel(vercel.com)에 GitHub 계정으로 로그인 → Add New → Project → samguk-gate-runner 저장소를 Import. Framework Preset은 Other. 그대로 Deploy.
4. 프로젝트 Settings → Environments(또는 Git) → Production의 Branch Tracking을 `deploy`로 바꾼다.
5. 프로젝트 Storage → Create Database → Neon(Postgres) → 이 프로젝트에 Connect. 환경 변수 `DATABASE_URL`이 자동으로 들어간다.
6. 프로젝트 Settings → Environment Variables에 `EXPORT_TOKEN`을 추가한다. 값은 남이 짐작할 수 없는 긴 문자열. 기록을 내려받을 때 쓴다.
7. Deployments에서 deploy 브랜치의 최신 배포를 Redeploy(환경 변수를 넣은 뒤에 한 번 다시 배포해야 적용된다).
8. 배포 주소를 휴대폰으로 열어 한 판 하고, 아래 "기록 받기"로 사건이 쌓였는지 확인한다.

## 그다음부터

- main에 푸시하면 자동으로 새 빌드가 배포된다. 빌드 이름(날짜-커밋)이 기록에 찍혀서 빌드별로 나눠 볼 수 있다.

## 기록 받기와 분석

```
python tools/analyze_logs.py --url https://<배포 주소> --token <EXPORT_TOKEN> --save events.jsonl --out 분석.md
python tools/analyze_logs.py --file events.jsonl --build 2026-11-13-abc1234
```

보고서에 나오는 것: 사람당 판 수(30판을 채우는가), 끝까지 가지 않은 판, 스테이지·장수별 돌파율, 진 판이 끝난 구간, 판 길이, 책략 선택률과 돌파율, 게이트 선택률, 적 무리 교전 길이, 보스전(길이, 공격에 맞은 비율), 결과 화면에서 누른 버튼, 강화 구매.

## 모으는 것과 모으지 않는 것

- 모으는 것: 무작위 기기 식별자, 판에서 고른 것과 결과, 걸린 시간, 화면 크기, 접속 나라 코드(Vercel이 붙여 주는 값).
- 모으지 않는 것: 이름, 계정, 연락처, IP 주소, 위치.
- 타이틀 화면 아래에 수집 사실을 적어 둔다. 테스터에게 주소를 줄 때도 알린다.

## PC에서 기록 보기

`data/tuning.json`의 `telemetry.local_file`을 true로 바꾸고 PC에서 실행하면 서버로 보내지 않고 `user://telemetry.jsonl`에 쓴다. 이 파일을 `--file`로 분석할 수 있다. 커밋할 때는 false로 되돌린다.
