## 책략을 출전 직전에 고르기, 책략 작동 표시 (2026-11-11)

  - 장수 모델은 시작 병종으로 고정이다. 병종 전환 게이트를 지나도 장수 모습은 바뀌지 않는다.
  - Compatibility 렌더러에서 MultiMesh에 인스턴스 사용자 데이터만 켜면 꼭짓점 색이 검게 나와, 인스턴스 색을 흰색으로 함께 넣었다.
  - 디버그 표시는 V1 지시대로 기본 꺼짐이다(이전 V4 지시는 기본 켜짐). 병력 증감(↑↓), 병종 전환(1~3), 감속(G) 단축키는 그대로 늘 동작한다.
  - 게이트 문구는 `gate_pair.gd`에서 새로 만든다(종류 이름 대신 아이콘). `Gate.label()`은 규칙 검사 메시지에만 남아 있다.
  - 장비 기술 원판과 제갈량 원판은 표시 대형 크기와 중심에 맞췄다. 동작과 시간은 그대로다.
  - 새 표현 값은 `data/visual.json`에 두었다. 이제 쓰지 않는 `tuning.json`의 `camera`, `hud.count_label_height`, `colors`의 `road`, `ground`, `marker`, `units.json` 세 병종의 `mesh`는 지우지 않고 남겼다(보스는 아직 `mesh`를 쓴다).
  - 좁은 다리, 보스, 화살, 책략 3택, 장수 선택, 결과 화면은 V2 범위라 글꼴만 바뀌고 그대로다.

## 단계 V0: 렌더러 전환 (2026-11-11)

- **만든 것**
  - `project.godot`의 렌더러를 Compatibility(`gl_compatibility`)로 바꿨다. 모바일 기본값도 같은 값으로 맞췄다. 씬과 스크립트는 고치지 않았다.
- **확인 방법**
  - 에디터 오른쪽 위 렌더러 표시가 Compatibility인지 본다. 실행하면 출력 창 첫 줄에 "OpenGL API ... Compatibility"가 나온다.
  - 전환 전후 캡처: `docs/스크린샷/V0_전_Mobile.png`, `docs/스크린샷/V0_후_Compatibility.png`
  - 헤드리스 가져오기, 메인 씬 실행, 단계 5 보충 자동 확인(1-6 세 장수)에서 스크립트 오류 없음.
  - 프레임(PC, RTX 3050, 540×960 창, 수직 동기 끔, 1-1 관우, 병사 200개 유지, 20초): Mobile 평균 0.87ms(약 1150fps), 하위 1% 3.49ms. Compatibility 평균 0.78ms(약 1290fps), 하위 1% 2.24ms.
- **명세와 다르게 구현했거나 명세에 없어서 정한 부분**
  - 지금 장면은 그림자, 안개, 후처리를 쓰지 않아 전환 전후 화면이 같다. 도로, 풀밭, 병사 색의 픽셀 값이 1 이내로 같았다.
  - 프레임 측정은 PC 값이다. 폰과 모바일 브라우저 값은 단계 6, 7에서 잰다.

## 단계 5 보충: 피해 숫자, 표시 배율, 장수 기술 표시, 무한 스테이지 (2026-11-11)

- **만든 것**
  - 평소 교전 피해 숫자: 앞 적 무리(보스 포함)에 실제로 깎인 체력을 0.5초마다 합산해 표시 배율(×100)을 곱해 머리 위에 하나씩 띄운다. 병력 수 팝업보다 작은 글자(40)로, HUD에서 병력 수와 변화량 팝업보다 아래 층에 그린다.
  - 장수 기술 표시(`scripts/hero_skill_view.gd` 신규)
    - 관우: 아군 앞에서 적 무리까지 늘어나는 직선 도형 0.3초, 맞은 무리 위에 피해 숫자 5~8개
    - 장비: 효과 3초 동안 아군 무리 주위 원판
    - 제갈량: 아군에서 퍼지는 원판 0.3초, 효과 4초 동안 병사 밝기 올림(계열 색 유지)
  - 무한 스테이지: 1-5 이후 1-6, 1-7…을 자동 생성한다. 적 병력 합계 ×1.15, 보스 체력 ×1.2를 단계마다 곱하고, 병종 비율은 한 병종 70% 이하, 좁은 다리는 30% 확률로 한 구간.
  - 장수 선택 화면의 스테이지 줄을 줄바꿈되는 배치로 바꾸고, 열린 자동 생성 스테이지를 보여준다.
  - 수치는 모두 `data/tuning.json`의 `display_damage_multiplier`, `damage_number`, `hero_skill_view`, `endless`에 둔다.
- **확인 방법**
  - 에디터에서 실행해 아무 장수로 교전하면 적 무리와 보스 위에 작은 숫자가 0.5초 간격으로 뜬다. 병력 수는 실제 값 그대로다.
  - 관우, 장비, 제갈량으로 각각 한 판씩 돌려 기술 발동 표시를 본다. 제갈량 계열 효과가 켜진 상태에서도 색은 계열 색 그대로 밝아지기만 한다.
  - 1-5를 클리어하면 결과 화면에 "다음"이 나오고 1-6으로 이어진다. 장수 선택 화면에도 1-6이 나타난다.
  - 헤드리스 시험(가져오기, 메인 씬 120프레임, 1-6에서 세 장수 각 70초 자동 진행): 스크립트 오류 없음. 1-6~1-12의 병력·보스 체력이 배율대로 늘고 최대 병종 비율은 0.36~0.61이었다. 장비 원판 표시 601프레임(발동 4회), 제갈량 밝기 723프레임(발동 3회)으로 지속 시간과 맞았다.
- **명세와 다르게 구현했거나 명세에 없어서 정한 부분**
  - 피해 숫자 값은 "실제로 깎인 체력"이다. 남은 체력보다 큰 피해(초과 피해)는 넣지 않는다. 화계, 불화살 지속 피해, 돌격도 평소 교전 숫자에 합산하고, 장수 기술 피해만 따로 띄운다.
  - 관우 피해 숫자 5~8개는 기술 피해 합계를 무작위 크기로 나눈 것이다. 숫자를 모두 더하면 실제 피해 × 표시 배율이 된다.
  - 제갈량의 퍼지는 원형 도형 시간은 명세에 없어 관우 직선과 같은 0.3초로 했다.
  - 장비의 "주위 원형 도형"은 고리가 아니라 무리보다 조금 큰 반투명 원판으로 그렸다.
  - 피해 숫자 글자 크기는 명세대로 구현하며 정했다: 40(병력 수 72). 명세 표에는 넣지 않고 `tuning.json`에만 있다.
  - 피해 숫자는 HUD 층이라 3D 게이트 글자보다 위에 그려진다. 배치상 적 무리와 게이트가 20m 이상 떨어져 있어 실제로 겹치는 일은 드물지만, 완전히 막지는 않았다.
  - 자동 생성 스테이지는 메모리에만 있어 게임을 껐다 켜면 구성이 새로 뽑힌다(저장은 단계 6).
  - 1회 클리어 금화 상한 1,000은 금화 지급과 함께 단계 6에서 넣는다. 이번에는 `tuning.json`에도 넣지 않았다.
