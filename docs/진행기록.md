## 책략을 출전 직전에 고르기, 책략 작동 표시 (2026-11-11)

지시는 작업지시.md (13). 확인은 작업한 세션의 리눅스용 Godot 4.7.2에서 했다.

- **만든 것**
  - 책략 선택 시점(기획 변경, `scripts/run.gd`, `data/strategies.json`의 `picks_per_run`): 출전하면 달리기 전에 3택 화면이 세 번 이어지고, 다 고르면 출발한다. 구간 끝에서는 멈추지 않고 다음 구간으로 넘어간다. 3택 화면 자체(`scripts/strategy_choice.gd`)는 그대로 쓰고 제목의 "n/3"만 고른 횟수가 된다.
  - 책략 작동 표시(`scripts/run.gd`, `scripts/gate.gd`): 증원 게이트의 변화량 아래에 책략으로 늘어난 몫을 "책략 +N"으로 붙인다. 접촉 순간 화계와 선봉의 이름을 적 무리 위에, 궁병이 아닐 때 불화살 일제 사격을 아군 위에 계열 색으로 띄운다. 의병 팝업도 계열 색으로 바꿨다.
- **확인 방법**
  - 자동 확인: 출전 직후 달리지 않고 "책략 선택 1/3"이 뜬다. 세 번 고르면 책략 3개를 가진 채 1구간에서 출발한다. 구간 경계를 지나면 2구간이 되고 책략 화면은 뜨지 않는다.
  - 징병을 가진 채 +20 게이트를 지나면 12 → 42명이고 팝업은 "+30 / 책략 +10"이다.
  - 1-5에서 장비로 불화살, 화계, 의병을 고르면 출발할 때 "의병 +10", 사거리 안에서 "불화살", 접촉 순간 "화계"가 뜬다.
  - 캡처: `docs/스크린샷/`의 P1_출전직전_책략, P1_책략표시_게이트, P1_책략표시_접촉.
- **명세와 다르게 구현했거나 명세에 없어서 정한 부분**
  - 의병(구간 시작 시 +10명)은 이제 1구간 시작과 보스전 시작에도 들어가 한 판에 네 번 적용된다. 전에는 고른 구간 다음부터라 최대 세 번이었다. 수치는 그대로 두었다.
  - 정병(즉시 병력 −40%)은 시작 병력에 적용된다. 장비 16명이면 10명으로 출발한다. 전에는 구간 끝의 불어난 병력에 적용됐다.
  - 선택 기록의 책략 줄은 구간을 0으로 적는다.
  - 철갑, 횡진, 연환, 계열 효과(공격력, 지속 피해)는 터지는 순간이 없어 표시하지 않는다.
  - P1_책략표시_게이트는 게이트 통과 번쩍임과 겹친 순간이라 팝업이 병력 숫자와 겹쳐 보인다. 팝업은 병력 숫자 위치에서 시작해 위로 올라간다(기존 동작).

## 플레이 후 게이트 조정: 전환 대상, 함정 짝, 선택될 칸 표시 (2026-11-11)

지시는 작업지시.md (12). 확인은 작업한 세션의 리눅스용 Godot 4.7.2에서 했다.

- **만든 것**
  - 전환 게이트 대상(규칙 변경, `scripts/stage_builder.gd`): 대상은 그 게이트 다음에 만날 적 무리에서 가장 많은 병종에게 유리한 병종이다. 수가 같으면 앞줄 순서(보병, 기병, 궁병)가 빠른 병종을 기준으로 삼는다. 적 무리 배치를 먼저 정한 뒤 게이트를 뽑도록 순서를 바꿨다.
  - 같은 병종 전환 교체(`scripts/gate.gd`, `scripts/gate_pair.gd`): 지나지 않은 전환 게이트의 대상이 아군 병종과 같으면 그 칸을 다른 종류로 바꾼다. 짝이 강화면 증원, 아니면 강화다. 앞 묶음의 "다른 병종으로 바꾼다"(`retarget_switch`)는 지웠다.
  - 함정 짝(규칙 변경, `data/gates.json`): 함정에 `pair_with: ["reinforce"]`를 넣어 도박처럼 증원(+N)과만 짝짓는다.
  - 선택될 칸 표시(`scripts/gate_pair.gd`, `scripts/run.gd`, `visual.json`의 `gate.preview_*`): 게이트 앞 12m 안에서 무리 중심 쪽 칸을 밝게(불투명도 0.5 → 0.8), 반대쪽 칸을 어둡게 한다. 판정과 같은 함수(`GatePair.side_for_x`)를 쓴다. 글자는 양쪽 다 그대로다.
- **확인 방법**
  - 생성 확인(1-1~1-10 각 20판, 게이트 쌍 1,488개): 전환 게이트 654개 모두 대상이 다음 적 무리의 최다 병종에게 유리한 병종이었다. 함정 275개 모두 짝이 증원(+N)이었다.
  - 1-1에서 제갈량(궁병, 적은 보병뿐)으로 시작하면 전환 게이트가 하나도 남지 않는다. 궁병 전환 게이트를 억지로 넣으면 다음 프레임에 강화 게이트로 바뀐다.
  - 선택 표시: 게이트 20m 앞에서는 꺼져 있고, 9m 앞에서 중심이 x=−1이면 왼쪽, x=0.6이면 오른쪽이 밝아진다. 오른쪽(+20)으로 통과하면 12 → 32명.
  - 캡처: `docs/스크린샷/`의 G1_선택표시_왼쪽, G1_선택표시_오른쪽.
- **명세와 다르게 구현했거나 명세에 없어서 정한 부분**
  - 전환과 강화가 짝이 되는 쌍은 그대로 나온다(1,488쌍 중 343쌍). 양쪽 다 병력이 줄지만 양쪽 다 얻는 것이 있다.
  - 제갈량으로 1-1을 하면 전환 게이트가 나오지 않는다. 적이 보병뿐이고 궁병이 이미 유리한 병종이기 때문이다.

## 단계 6: 영구 강화, 금화, 저장, 웹 내보내기 (2026-11-11)

**안드로이드 빌드와 폰에서의 병사 200개 프레임 확인은 하지 않았다.** 작업한 세션에 안드로이드 SDK와 폰이 없다. 단계 6 완료 조건 세 가지 중 이것 하나가 남았다.

- **만든 것**
  - 금화(`scripts/game_state.gd`, `tuning.json`의 `gold`): 클리어 100 × 스테이지 번호(상한 1,000), 실패는 그 30%. 함정 게이트 금화는 상한과 별도로 더한다. 판이 끝나면 지급하고 결과 화면에 "금화 +200 (함정 +100 포함)"처럼 보여준다.
  - 영구 강화(`data/upgrades.json`, `scripts/game_state.gd`): 병영(레벨당 시작 병력 +2, 비용 100 × 다음 레벨), 무기고(레벨당 공격력 +5%, 비용 150 × 다음 레벨). 판을 시작할 때 시작 병력에 더하고 `army.attack_mult`에 곱한다(`scripts/run.gd`).
  - 강화 화면(`scripts/upgrade_screen.gd`, `scenes/ui/upgrade_screen.tscn`): 보유 금화, 시설마다 레벨과 "지금 효과 → 다음 효과", 올리기 버튼(금화가 모자라면 회색). 카드와 닫기 버튼은 화면 아래쪽에 모았다. 장수 선택 화면(출전 버튼 위)과 결과 화면의 "강화" 버튼으로 연다.
  - 저장(`user://save.json`): 금화, 강화 레벨, 열린 스테이지 수, 고른 장수와 스테이지, 자동 생성 스테이지 구성. 판이 끝날 때, 강화를 살 때, 출전할 때 저장하고 게임을 켤 때 읽는다.
  - 장수 선택 화면: 장수 카드의 시작 병력에 병영 강화분을 더해 보여준다. 금화와 강화 버튼 줄이 들어가도록 카드 높이를 340 → 300으로 줄였다.
  - 장수 선택 화면 스테이지 줄(`scripts/hero_select.gd`, `scenes/ui/hero_select.tscn`): 스테이지 버튼을 한 줄로 놓고 5개만 보이게 했다. 1-6 이후가 열리면 줄을 좌우로 밀어서 고르고, 화면을 열 때 고른 스테이지가 보이도록 줄을 맞춘다. 9개가 열린 상태에서 화면이 넘치지 않는 것을 캡처(S6_장수선택_9개열림)로 확인했다. 명세 5장 V2 세부의 "한 줄에 5개씩"과 달리 둘째 줄을 만들지 않는다.
  - 웹 내보내기(`export_presets.cfg`): 스레드 없는 Web 프리셋, 출력은 `build/web/index.html`. data의 JSON이 빌드에 들어가도록 포함 필터에 `data/*.json`을 넣었다. `build/`는 `.gitignore`에 넣었다.
- **확인 방법**
  - 자동 확인(리눅스용 Godot 4.7.2): 보상 1-1 클리어 100, 1-3 실패와 함정 100은 90 + 100, 1-12 클리어 1,000. 금화 0으로는 살 수 없음. 병영 1레벨 뒤 금화 200 → 100, 다음 비용 200. 병영 1, 무기고 2에서 장비 시작 병력 18명, 공격 배율 1.1. 저장 뒤 메모리를 흩뜨리고 다시 읽으면 금화, 레벨, 열린 스테이지, 장수, 스테이지, 1-7 구성이 그대로다.
  - 웹 빌드: 내보낸 빌드를 로컬 서버로 띄워 크롬(헤드리스)에서 열었다. 장수 선택 화면이 뜨고 출전을 누르면 달리기가 시작된다. 오류 로그 없음.
  - 캡처: `docs/스크린샷/`의 S6_장수선택, S6_강화_구매전, S6_강화_구매후, S6_결과_승리, S6_결과_패배, S6_웹빌드_달리기.
  - 에디터에서: 한 판을 끝내 금화를 받고, 강화를 올리고, 게임을 껐다 켜서 금화와 레벨이 남아 있는지 본다. 웹은 에디터의 프로젝트 > 내보내기에서 Web 프리셋으로 내보낸다(내보내기 템플릿 설치 필요).
- **명세와 다르게 구현했거나 명세에 없어서 정한 부분**
  - 함정 금화는 상한과 별도, 실패한 판에도 지급. 실패 보상은 상한 적용 뒤 30%. 명세 3장에 반영했다.
  - 강화 화면은 장수 선택이나 결과 화면 위에 겹쳐 띄운다. 명세 2장의 화면 전환(결과 → 강화)과 달리 따로 거치는 단계가 아니라 버튼으로 여는 화면이다.
  - 저장 파일에 명세가 말한 "영구 강화 수치" 외에 열린 스테이지, 고른 장수와 스테이지, 자동 생성 스테이지 구성을 함께 넣었다(진행기록 단계 5, 5 보충에서 단계 6으로 미룬 것).
  - 저장을 지우는 버튼은 없다(알려진_문제.md).

## 단계 V3 조정: 보스 판정, 같은 병종 전환 게이트, 게이트 글자 (2026-11-11)

지시는 작업지시.md (10). 확인은 작업한 세션의 리눅스용 Godot 4.7.2(소프트웨어 렌더러)에서 했다. 사용자 PC의 에디터에서는 아직 실행하지 않았고, 프레임은 재지 않았다.

- **만든 것**
  - 보스 판정(규칙 변경, `scripts/boss.gd`, `scripts/run.gd`, `scripts/boss_view.gd`): 공격 순간 아군 표시 대형의 좌우 끝이 공격 구역에 걸쳐 있으면 맞는다. `BossPattern.tick`이 구역 번호 대신 무리의 좌우 끝 x를 받는다. `hit_zone_of`, `hit_range`를 지우고 `overlaps_zone`, `zone_range`를 넣었다. 예고 면은 구역 전체(폭 5m)에 그린다. `tuning.json`의 `boss.hit_margin`(0.5)을 `boss.hit_edge_tolerance`(0)로 바꿨다.
  - 같은 병종 전환 게이트(규칙 변경, `scripts/gate.gd`, `scripts/gate_pair.gd`, `scripts/run.gd`): 지나지 않은 전환 게이트의 대상이 아군 병종과 같으면 나머지 두 병종 중 하나로 무작위로 바꾸고 판을 다시 그린다. 매 프레임 확인하므로 판 시작 때와 앞 게이트에서 병종이 바뀐 직후에 적용된다.
  - 게이트 글자(`scripts/gate_pair.gd`): 주 효과 글자를 칸마다 따로 정한다. 긴 쪽은 판 폭의 82%, 짧은 쪽은 긴 쪽 글자 크기의 1.5배까지(`visual.json`의 `gate.main_short_scale_max`). 대가 글자는 좌우가 같고 긴 쪽 주 효과의 70%. 글자 묶음을 위로 올렸다(아이콘 6.25 → 6.45m, 주 효과 4.15 → 4.6m, 대가 2.25 → 3.0m).
  - 장수 깃발(`visual.json`의 `hero.flag`): 깃발 중심을 4.6m → 3.5m(장수 2배 크기 기준)로 낮추고 깃대를 줄였다.
  - 겹침 화면(`scripts/run.gd`, `scripts/hero_view.gd`): 책략 선택과 결과 화면이 뜨면 게이트 글자와 깃발 글자를 숨긴다. 책략을 고르면 다시 켠다.
  - 장수 선택(`scripts/hero_select.gd`, `scripts/hero_view.gd`): 모델 화면에 밝은 바탕색(`hero_ui.model_back`)을 깔았다. 깃발 앞면에도 이름 글자를 붙였다. 잠긴 스테이지 글자색을 밝혔다(`hero_ui.stage_locked_text`).
- **확인 방법**
  - 메인 씬 헤드리스 200프레임, 달리기 씬 자동 진행(세 장수)에서 스크립트 오류 없음.
  - 보스 판정 자동 확인(병력 200명, 무리 반폭 2m, 이동 범위 ±3m): 가운데(x=0)에 서 있으면 200 → 150, 반대쪽 끝(x=3)이면 200 → 200, 안전 지점에서 0.3m 안쪽(x=1.7)이면 200 → 150.
  - 전환 게이트 자동 확인: 보병일 때 "보병 전환"으로 만든 게이트가 궁병 전환으로 바뀌었고, 궁병으로 바꾸자 다시 보병 전환으로 바뀌었다.
  - 책략 선택 화면이 떠 있는 동안 보이는 게이트 글자 노드 0개.
  - 보스전: 가운데에 가만히 서 있으면 좌우 어느 공격에도 맞는다. 붉은 면 반대쪽 끝까지 가면 맞지 않는다.
  - 게이트: 전환 게이트가 지금 병종과 같은 병종으로 나오지 않는다. "+10" 같은 짧은 문구가 전보다 크다.

  - 보스 모델 크기와 화살 크기는 `visual.json`의 `model_scale`(보스 1.6, 화살 1.5)로 키웠다. 계산에는 쓰지 않는다.
  - 결과 화면에 "장수 선택" 버튼을 남겼다(작고 어둡게, 다시 도전 위).
  - 책략 카드의 계열 진행도와 발동 미리보기를 위해 `strategy.gd`에 읽기 전용 함수(`family_ids`, `bonus_count`, `family_count`, `would_activate`)를 더했다. 계산 결과는 바뀌지 않는다.
  - 표현 값만 바뀌어 쓰지 않게 된 값을 지웠다: `tuning.json`의 `boss.label_height`, `label_font_size`, `label_pixel_size`, `arrow_view.size`, `color`, `colors.bridge`, `colors.water`, `hero_skill_view.alpha`. 새 표현 값은 `visual.json`(`strategy_ui`, `hero_ui`, `result_ui`, `boss_view`, `bridge`, `clash`, `skill_view`, `arrow`, `model_scale`)에 두었다.
  - 길가 돌 표지(도로 가장자리 회색 상자)는 다리 위에도 그대로 놓인다.

## 단계 5 보충: 피해 숫자, 표시 배율, 장수 기술 표시, 무한 스테이지 (2026-11-11)

  - 에디터에서 실행해 아무 장수로 교전하면 적 무리와 보스 위에 작은 숫자가 0.5초 간격으로 뜬다. 병력 수는 실제 값 그대로다.

- **명세와 다르게 구현했거나 명세에 없어서 정한 부분**
  - 피해 숫자 값은 "실제로 깎인 체력"이다. 남은 체력보다 큰 피해(초과 피해)는 넣지 않는다. 화계, 불화살 지속 피해, 돌격도 평소 교전 숫자에 합산하고, 장수 기술 피해만 따로 띄운다.
  - 관우 피해 숫자 5~8개는 기술 피해 합계를 무작위 크기로 나눈 것이다. 숫자를 모두 더하면 실제 피해 × 표시 배율이 된다.
